# pi-stargate - Hostapd Troubleshooting Chat
## Date: 2026-11-18

## Initial Problem
- User tried `ssh antonio@192.168.255.3` to connect to Raspberry Pi
- `hostapd` not working - AP failed to start

## Diagnosis & Fixes Applied

### 1. Country Code Mismatch (PRIMARY FIX)
- **Issue**: `hostapd.conf` had `country_code=US` but Pi's wireless regulatory domain is `DE` (DFS-ETSI)
- **Debug evidence**: Log showed `country=DE (DFS-ETSI)` but config had `US`
- **Fix**: Changed `country_code=US` → `country_code=DE` in `/etc/hostapd/hostapd.conf`

### 2. Channel Conflict
- **Issue**: After country code fix, AP started on channel 1 instead of configured channel 11
- **Fix**: Ensured `channel=11` remains in config

### 3. Install Script Enhancement
- Added `sudo /usr/local/sbin/sync-ap-channel` to `install.sh` (line 89-90)
- This syncs AP country code and channel from wlan0 on first boot
- Ongoing sync handled by `watch-ap-channel.timer` (every 30s)

### 4. ap0.service Fix
- Uncommented `ExecStartPost=/usr/sbin/ip link set ap0 up` in `/etc/systemd/system/ap0.service`
- Ensures AP interface is brought up before hostapd starts

### 5. hostapd.service Capabilities
- Added to `/lib/systemd/system/hostapd.service`:
  ```
  CapabilityBoundingSet=CAP_NET_ADMIN CAP_NET_RAW
  AmbientCapabilities=CAP_NET_ADMIN CAP_NET_RAW
  ```
- Gives hostapd permissions needed to configure wireless interface
