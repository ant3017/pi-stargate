## DNS / resolvconf — solved

- Root cause of the recurring resolv.conf reset: the Pi runs **openresolv 3.12.0**, not Debian resolvconf.
- openresolv writes `/etc/resolv.conf` directly (regular file, not a symlink) from its records + `/etc/resolvconf.conf`.
- `resolv.conf.d/{head,base,tail}` and `update.d/libc` are **Debian-resolvconf-only** — both absent/ignored here (update.d contained only `dnsmasq.disabled`, confirming the earlier mv worked).
- Correct openresolv override:

  ```bash
  echo 'name_servers=1.1.1.1' | sudo tee -a /etc/resolvconf.conf
  sudo resolvconf -u
  ```

  `name_servers` entries are written **before** interface records; `name_servers_append` goes last. (`prepend_nameservers` does not exist in openresolv — silently ignored.)
- `search wind3.hub` = DHCP search domain from the WindTre router, harmless.
- Nuclear option documented if NM keeps stomping the file: `chattr +i /etc/resolv.conf`.

## pi-config scripts

- **`install.sh`** — found and fixed a mangled resolvconf block (missing `#` on a comment + scrambled `if/fi` → syntax error). Final order:
  1. `mv update.d/dnsmasq → dnsmasq.disabled` (kills the 127.0.0.1 registration)
  2. append `IGNORE_RESOLVCONF=yes` to `/etc/default/dnsmasq` (guard, prevents lo.dnsmasq on restart)
  3. append `name_servers=1.1.1.1` to `/etc/resolvconf.conf` (openresolv prepend)
  4. fallback: pin `nameserver 1.1.1.1` in resolv.conf if no real NS remains
- **`capture.sh`** — FILES now = the 19 deployed files + 3 runtime-state files (`etc/resolvconf.conf`, `etc/default/dnsmasq`, `etc/resolvconf/update.d/dnsmasq.disabled`).
- **`restore.sh`** — generic `files/` walker (no list needed); added post-restore fixup: if snapshot contains `dnsmasq.disabled` but a fresh package install re-created a live `update.d/dnsmasq`, move it again.
- New bundle files: `files/etc/iptables/rules.v4` (FORWARD+MASQUERADE persists via netfilter-persistent before runtime `-A` checks) and `files/etc/resolvconf/resolv.conf.d/tail`.
- Design split confirmed: `install.sh` = minimal append-guards for shared files; `capture`/`restore` = full-fidelity snapshots.
