# Chat log summary — Pi WiFi bridge + captive portal (2026-11-13)

Device: Raspberry Pi "stargate" (Raspberry Pi OS/Debian, user `antonio`).
Goal evolved across the session:

1. Bridge: laptop → Pi WiFi AP → router → WireGuard (`wh0`, not `wg0`)
2. Same single radio for both AP and STA (no eth0, no second adapter)
3. Captive provisioning portal on the AP to pick/test/save upstream WiFi

## Interface map

- `wlan0` — STA uplink to router (netplan → wpa_supplicant → networkd, DHCP)
- `ap0` — virtual AP for laptop (hostapd + dnsmasq, 192.168.50.1/24)
- `wh0` — WireGuard tunnel endpoint (192.168.255.3)
- `usb0` — phone USB tether (temporary internet for apt)
- `eth0` — present but unused (no carrier)

## Core constraint

One radio = one channel. `ap0` must share whatever channel `wlan0`
associated on — and it must be 2.4 GHz (5 GHz channels showed
`disabled`/`no IR`, radio can't beacon).

## Working configs (final)

- `/etc/netplan/60-wifi.yaml` — `wifis.wlan0`, `dhcp4`, `access-points`
  entries each with `band: 2.4GHz`
- `/etc/hostapd/hostapd.conf` — `interface=ap0`, `hw_mode=g`, hardcoded
  `channel=` (NO `country_code`, NO `channel=acs`), `ctrl_interface`
- `/etc/default/hostapd` — `DAEMON_CONF="/etc/hostapd/hostapd.conf"` +
  `systemctl unmask hostapd`
- `/etc/systemd/system/ap0.service` — creates `ap0` via `iw` before hostapd
- `/etc/systemd/network/10-ap0.network` — static `192.168.50.1/24`
- `/etc/dnsmasq.d/ap0.conf` — DHCP on ap0, `port=0` (no DNS, avoids resolved)
- iptables — `FORWARD ap0<->wh0`, `MASQUERADE -o wh0`,
  `net.ipv4.ip_forward=1`
- Auto-adapt: `/usr/local/sbin/sync-ap-channel` (reads wlan0 channel →
  sed hostapd.conf → restart hostapd) + `watch-ap-channel` 30 s timer

## Pitfalls hit (all real)

1. `netplan apply` OVS error → ovsdb not running; start it or remove
   `openvswitch-*` packages providing `ovs-vsctl`.
2. `Failed to initiate sched scan` → radio busy: stale AP mode / duplicate
   wpa_supplicant. Fix: `iw dev wlan0 set type managed`, one supplicant only.
3. hostapd dies at `COUNTRY_UPDATE` → `country_code=` conflicts with
   regdomain adopted from router's country IE. Fix: remove it.
4. hostapd dies after `ACS-STARTED` → `channel=acs` can't survey while a
   STA is associated. Fix: hardcode channel.
5. AP invisible on channel 44 / 5230 MHz → 5 GHz DFS, `no IR`/`disabled`.
   Fix: lock STA to 2.4 GHz (`band: 2.4GHz` or `freq_list`).
6. `ExecStartPre` calling `systemctl restart hostapd` → recursion kills the
   unit (`signal=TERM`, "repeated too quickly"). Never restart the service
   from its own ExecStartPre; `systemctl reset-failed` to unlatch.
7. `deb.debian.org` DNS failure → `/etc/resolv.conf` nameserver fix /
   USB tether for internet.
8. Lost AP access → USB gadget mode (`dtoverlay=dwc2`,
   `modules-load=dwc2,g_ether` in cmdline.txt) for SSH over USB;
   USB phone tether for internet.

## Captive portal (new feature — files in this folder)

Request: AP shows a page listing visible WiFi networks; user picks SSID +
password; password is tested by associating; if it works, saved to netplan
for next time; if the upstream network itself has a captive portal, that
portal must be shown for login.

Built:

- `wifi_portal.py` — Flask app on `192.168.50.1:80`
  - GET any path → page (catch-all for captive-portal probes)
  - POST /connect → write netplan entry → `netplan apply` → poll
    association 30 s → keep on success, revert on failure
  - `band: 2.4GHz` auto-added to every saved network
  - background `manager_loop` every 30 s:
    - `generate_204` probe → online: route via `wh0`, DNS normal
    - hijacked probe → upstream portal: route ap0→wlan0 direct so the
      upstream portal can intercept the laptop; back to `wh0` when done
    - no uplink → dnsmasq catch-all DNS (`address=/#/192.168.50.1`) so
      the OS auto-opens our page
- `wifi-portal.service` — systemd unit
- `INSTALL.md` — deploy + design notes

## Known limits

- Single radio ≈ half throughput; 5 GHz-only routers unusable by design
- Wrong password = ~30 s association timeout (no clean bad-PSK signal)
- Portal runs as root (iptables/netplan/iw) — private-AP scope only
- USB WiFi dongle removes all channel coupling if this proves fragile
